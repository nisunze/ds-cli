If an entry turns out to need a code change, move that part to [OPEN.md](OPEN.md) and keep only the seeding or acceptance part here. Unresolved owner decisions, authority and supervised steps are in [OPEN-X.md](OPEN-X.md); the standing rulings are in [PRINCIPLES.md](PRINCIPLES.md).

Discover the live contract, review the exact project/revision/digest and apply only authorized effects through `ds`. Build locally and deploy the exact local artifact; an agent never starts remote Cloud Build/CI. On Windows, delivery remains in the project G: folder with the Desktop shortcut and verified bytes.

Pens, colour/opacity, contour hierarchy, labels, extent, margins, title/issue fields and supported schedule/font controls are document choices. Render actual pages at print scale and verify preview/download/publication. If an admitted value is ignored, a required control is absent, or valid settings still cause overflow/clipping, add that exact measured code defect to OPEN.md. A tuned page, digest match or clean backup roundtrip does not confer engineering approval.

Candidate curation and native PLS-CADD acceptance are separate from coding the cloud/provider-model lifecycle. Existing local seed/verify/resolve and global preparation/publication/lifecycle CLI contracts are present; they do not establish that every model-management or UI action is implemented. Older entries are pending verification, not proof of a current defect. Delete fulfilled work; do not keep a historical fixes archive.
