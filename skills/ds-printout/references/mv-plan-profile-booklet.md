# MV plan/profile booklet and one-shot delivery

Use this when delivering an MV plan/profile set, whether a selected proof or
a complete model. Resolve the project setup through its current project
records and the live DS contract. The setup, model revision, library digest,
context recipe and output receipts belong to the project. Keep the command
and options in the project's maintained driver/configuration; do not copy
machine-specific paths into the skill. An engineer should be able to preview
the effective setup, start one job, follow progress and inspect named
conflicts without supervising every sheet.

## Standard and atomic job

Start from the single governed MV A3 booklet standard in the existing printing
library. The pure standardization intent retains the approved cover and naming
pages and adds sheet index, key plan, legend/general notes and plan/profile
sheets. Its initial sheet defaults are native A3 landscape, H/plan 1:1500,
V 1:500, profile above plan, vertical structure labels, reference accent inks,
local elevation breaks and ground-guide-anchored extra clearance hairs.
The project adopts and selects an exact library revision once. A print request
binds geometry and held assets; it does not ask an agent to redesign front matter.
An intentional project template revision may override declarative layout and
sheet settings within the kernel's physical and engineering-display limits.

1. Verify the model revision, adopted setup digest, approved parties, contract,
   logo bytes, simple submission version and fixed issue date through their
   owners. The cover/naming migration retains approved PDF bytes; no generated
   inventory replaces an approved naming page. Native names are never changed
   to agree with display grammar. Unverified canonical member mapping remains
   a library-owner issue, not authority to invent examples.
2. Discover the JSON print job and preview contracts. A complete PNG inventory
   includes the cover, preserved pages and every engineering sheet. Inspect
   the portable booklet plan and raster hashes. Preview and PDF consume the
   same final laid-out pages; a preview-only run can precede PDF assembly.
   The kernel/WASM preview document is the same admission used by the native
   renderer, with ordered page identities, physical dimensions and PNG/raster
   hashes. A host should show that document, not reconstruct page positions.
3. Run one project JSON job. All booklets, previews and receipts stage together
   and commit as one fresh directory after success. A failed later component
   leaves no completed-looking destination and never overwrites prior delivery.
   Printing occurs on Server/Desktop; no cloud render or script assembler.
4. Compare the layout-plan digest and decoded raster hashes when rerunning
   the same model/setup. PDF serialization metadata is not the repeatability
   authority. Keep golden fixture evidence and real-page QA for changed layouts.

## Governed front matter and booklet order

Every page, including front matter, is A3 landscape at its native size:

Start from the exact published MV sample in the governed printing library,
adopt its revision into the project, and keep front matter and general setup
in that project template. Read the live `report.project.mv-setup` and
`report.plan-profile` contracts: the native booklet route resolves the selected
revision, model bindings and held approved assets before rendering. A ds-work
HTML/Python assembly is a historical delivery bridge, not the next-export
authority. Verify exact parties and logo bytes through project records and
assets. A missing contract number stays absent until verified. Preview the
effective front matter beside the project key map and a representative sheet
at paper size before making the full booklet. If this host cannot read the
governed template or the project-owned facts through its declared DS surface,
name the missing access or command in feedback and stop that booklet job.
Do not redraw a cover from a screenshot, borrow another project's branding,
or fill a blank with a plausible value.

1. Cover: project and document names, exact formal client, employer,
   consultant, contractor, logos and contract number where available in
   project records. Do not invent parties, signatures, approvals or a
   construction status. Use one simple document version.
2. Structure naming convention: preserve the exact approved page and exact
   native model names. Never replace it with a placed-type inventory or rewrite
   stay/class ordering per run. A canonical-code/member mapping needs its own
   verified library authority. Record unresolved mappings and an approved page's
   grammar discrepancy in the internal receipt for a governed future revision.
3. Sheet index and key plan: generated from the final same-revision sheet
   windows, with station ranges and actual scales. Key map: show the model's location in appropriate geographic context.
   Use the exact model revision; label transformers by their actual project
   names, at a readable A3 size without crowding. Keep roads, power lines and
   a small set of relevant places; omit rivers and settlement-site detail at
   this overview scale. Record missing source names internally instead of
   substituting another field without authority.
4. Legend and general notes precede numbered plan/profile sheets for that model, with the model identity and
   revision traceable to the booklet. For multiple models, use separate
   booklets or a clearly indexed combined set; do not mingle revisions.

Print `DS GridDesign by datasolutions.rw` discreetly and legibly on every
page, clear of engineering content. Confirm page dimensions, page count,
sequence, identity, version and credit on the assembled PDF itself. Use the atomic governed booklet route where its declared inputs meet the job;
report a concrete missing input or refusal rather than rebuilding that route.
A local render is not verified online delivery.

## Plan/profile context

Prefer alignment-keyed context pinned to its held geographic sources and style
recipe. The same capture serves all new sheet windows for that alignment and
survives MV revision changes. Do not include captured MV geometry: the exact
native plan owns both the main route and connected T-off first spans. A changed
context digest refuses; mixed keyed/positional inventories and duplicate keys
refuse. Legacy positional captures still require exact model revision and count;
migrate them deliberately instead of restamping old MV context.

North arrows, legends and deflection captions respect measured paper exclusions.
If no legal furniture position exists, the job refuses rather than drawing over
structure labels. Profile labels use their own elevation section's datum and
stay below the reserved scale band. Clearance receipts preserve observed Z,
guide anchor, extra, native threshold and display-wire margin; the renderer
refuses an inconsistent native display margin. This display check is not a new
engineering compliance study.

Carry the governed project context at the sheet window: terrain, roads,
shared MV/LV building footprints, existing and new LV, rivers, settlement
sites and prohibited zones where present. Style rivers blue and named rivers
with natural italic labels; distinguish new LV with darker blue. Show
administrative unit names in a readable hierarchy and natural orientation,
without administrative boundary strokes. Settlement-site outlines may show.
Keep context subordinate to the line, but record any required layer that is
missing or omitted. The key map may use administrative boundaries where its
purpose requires them; the no-boundary rule above is for plan/profile sheets.

LV here is context in one bluish family graded by importance, under the red
MV route. It never takes the categorical cable and structure palette of a
standalone LV transformer sheet, and a booklet instruction never restyles those
sheets: see [two LV print modes](../../ds-map-composition/references/transformer-sheets.md#two-lv-print-modes).

A project can explicitly accept an empty prohibited-zone table for a
particular model. For Nyamagabe-Nyaruguru Model 2, the owner accepted that
condition on 27 September 2026. Carry it in that model's setup and delivery
notes. Do not generalize it to Model 1 or other projects, and do not remove
the prohibited-zone layer from the print recipe.

Inspect the physical pages, not just render status: front matter typography,
key-map transformer names, context colors and labels, title blocks, legibility,
clipping and sheet sequence. Preserve hashes, QA scope and omissions in the
project delivery record. A selected proof is labeled as such; it is not a
complete print set.

## Submission outputs and separate palettes

The booklet is one item of the canonical MV submission set; read
[MV submission deliverables](../../ds-project-work/references/mv-submission-deliverables.md)
for the rest. Staking remains XLSX and never becomes printed pages; this
workflow prints only the booklet. The five native PLS reports do not authorize
PLS-CADD plan/profile printing.

Keep the main MV conductors and route pens from the approved project baseline.
Subdue LV/customer/context colours in the MV plan independently of the LV
transformer sheet's categorical engineering pens. A background palette from
an MV booklet is not a new default for individual LV transformer prints.
Special-code dots, hairs and captions use the admitted ground-offset guide;
terrain coordinates and engineering thresholds retain their source values.
When the requested description is the existing staking workbook column, bind
that exact source using the native plan/profile source schema; a library
description is not proof of equality to the delivered workbook. Preserve
number/name/XY and revision/source-byte pins, native comments and engineering
tags. Use the explicit structure-description label field where a separate row
is wanted. Do not edit model facts or invent material/stay/voltage wording for
printing. Inspect complete labels around native angle text and conductor
curves, including the project's known dense cases.

## Model-bound delivery

A local booklet receipt records the exact model revision; a local output is not
an attachment or a published map. Publish through the design-attachment owner
on the exact MV model/content revision using one logical plan/profile attachment
per model. Advance its latest pointer for a new iteration, retain the earlier
revision in history, and verify remote bytes through that owner. Never publish
MV booklets under project-wide map groups. UI/catalogue migration of existing
map entries belongs to those owners and must be verified separately.

## Governed paper appearance

Consume one kernel/API style resolution per declared entity, source kind, print
target and role. Focused/context and live/tile/cold are independent dimensions;
existing/new remains source data. The MV paper binding is `(mv_booklet,
project_model, print, project)`. Pens and scaling, fonts and label sizes, halos,
casing/dashes and index typography belong to the resolved document or adopted
Layout. Source-pinned context carries explicit queries and exact API replies.
Never construct a style id, seed a style, or recolour an SVG to simulate context.
An unavailable resolver/default refuses; print-styles owns governed API seeding.

Protect delivery by rendering the standard fixture from the baseline and branch
twice. Compare every matched PDF page as rasters, with thumbnails and a table of
differences traced to feedback or an owner rule. Added pages are explicit rows.
An unexplained difference blocks merge. Synthetic fixtures prove code behaviour;
they do not approve Nyamagabe assets or establish verified online delivery.
