# MV plan/profile booklet and one-shot delivery

Use this when delivering an MV plan/profile set, whether a selected proof or
a complete model. Resolve the project setup through its current project
records and the live DS contract. The setup, model revision, library digest,
context recipe and output receipts belong to the project. Keep the command
and options in the project's maintained driver/configuration; do not copy
machine-specific paths into the skill. An engineer should be able to preview
the effective setup, start one job, follow progress and inspect named
conflicts without supervising every sheet.

## Prove, then run

1. Verify the exact model and library revisions, project-owned setup and
   accepted conditions. The spotting skill covers the selected-alignment
   engineering proof. Render a selected plan/profile sheet through the same
   route and inspect it at physical paper size before launching the full set.
2. Seed required print context once at project scale where coverage is
   available; print sheets from held coverage using bounded focus or area
   windows. A sheet read must not silently acquire new provider data.
   Record omitted layers with their causes. Reuse other project reports only
   when their source, recipe and dependency digests are fresh; forced
   generation overrides reuse. A failed component need not discard fresh
   independent reports.
3. Run the full model as one project-owned job, with progress, bounded
   retries for declared transient read failures, and separate receipts for
   each model. Rendering occurs on Desktop or Server. Cloud storage may
   carry the result, but the cloud must not render it. Do not start a full
   print merely because a selected proof succeeded when the operator has
   reserved the full-job decision.

## Booklet order and paper

Every page, including front matter, is A3 landscape at its native size:

1. Cover: project and document names, project logo where governed, exact
   formal client, employer, consultant, contractor and contract number
   available in project records. Do not invent parties, signatures,
   approvals or a construction status.
2. Structure naming convention: the current governed library and a
   digest-linked naming key. The stay indicator precedes the structure
   strength/class in the canonical grammar. Mark unresolved legacy names
   or pending library members instead of implying migration is complete.
3. Key map: show the model's location in appropriate geographic context.
   Use the exact model revision; label transformers by their actual project
   names, at a readable A3 size without crowding. Mark source names that
   are missing instead of substituting another field without authority.
4. Numbered plan/profile sheets for that model, with the model identity and
   revision traceable to the booklet. For multiple models, use separate
   booklets or a clearly indexed combined set; do not mingle revisions.

## Plan/profile context

Carry the governed project context at the sheet window: terrain, roads,
shared MV/LV building footprints, existing and new LV, rivers, settlement
sites and prohibited zones where present. Style rivers blue and named rivers
with natural italic labels; distinguish new LV with darker blue. Show
administrative unit names in a readable hierarchy and natural orientation,
without administrative boundary strokes. Settlement-site outlines may show.
Keep context subordinate to the line, but record any required layer that is
missing or omitted. The key map may use administrative boundaries where its
purpose requires them; the no-boundary rule above is for plan/profile sheets.

A project can explicitly accept an empty prohibited-zone table for a
particular model. For Nyamagabe-Nyaruguru Model 2, the owner accepted that
condition on 27 September 2026. Carry it in that model's setup and delivery
notes. Do not generalize it to Model 1 or other projects, and do not remove
the prohibited-zone layer from the print recipe.

Inspect the physical pages, not just render status: front matter typography,
key-map transformer names, context colors and labels, title blocks, legibility,
clipping and sheet sequence. Preserve hashes, QA scope and omissions in the
project delivery record. A selected proof is labeled as such; it is not a
complete print set.
