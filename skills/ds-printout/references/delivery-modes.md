# Choose the output and its authority

| Requested deliverable | Workflow |
|---|---|
| Finished transformer sheets, MV booklet, district sheet or atlas | `ds-printout`, then its matching mode reference |
| Extent, furniture, legend or a per-transformer print exception | `ds-map-composition` |
| Print colours, fields, casing or line type | `ds-style-composite` |
| Combined LV plans, quantities workbook and geospatial files | The project's combined-delivery skill/configuration; `ds-report-consumption` for workbook facts |
| One row per transformer with voltage-drop coverage | The project's voltage-drop overview workflow; `ds-lv-voltage-drop` for producer results |
| Staking/BOQ reconciliation | `ds-grid-project-model`, `ds-boq-staking-table` or `ds-boq-combined-report` |
| Native PLS backup portability | `ds-pls-cadd-backup-delivery`; never a printing route |

Do not substitute a compounded ZIP for a combined multipage PDF or concatenate
individual electrical reports and call that a transformer overview. Report
complete, incomplete, refused and reserved coverage truthfully. Reports render
the pinned producer's electrical JSON; styling does not recalculate verdicts.

MV wire geometry and phase/shield pens remain the approved foreground.
Secondary LV/customer context is subordinate, with matching body/halo and
legend. Keep role, lifecycle and focus independent: MV/LV, transformers, main
circuits, services, customers and poles retain their distinct governed pens;
proposed/existing comes from each feature, with an explicit unknown fallback.
A new transformer does not make existing LV new, and context is not a lifecycle.
Standalone LV sheets retain their own categorical palette. Display
temperature, initial/final state and wind are drawing choices; retain the
separate governing engineering case and criteria. A project's colours,
temperatures, counts or accepted residuals never become global defaults.

For a requested staking Description column, bind the actual held workbook
through the native plan/profile configuration. Discover the exact source schema
through `report.plan-profile-config.schema`, and the render command through
`report.plan-profile`. The binding pins project, model revision, workbook bytes,
sheet/header/column, structure number, native name and X/Y. A library fallback
does not establish equality to a cleaned delivered column. Bind only print text;
do not edit model descriptions to make a print match. Preserve native names,
earthing, DOF, transformer, angle and special tags. Do not infer material,
voltage, stays or an expanded code. Complete descriptions wrap without ellipses.

Special hairs use the project's explicit hair-anchor setting and canonical
feature-clearance facts. Ground-offset hairs show only the extra height above
the visual guide; absolute thresholds, surveyed terrain and margins remain
unchanged. Ordinary guide connectors are not special hairs. Check actual feature
codes and threshold values rather than trusting a drawn marker's name.

New descriptions must clear native angle tags, conductor curves and existing
text, as well as each other and their containing panel. Inspect dense adjacent
structures and long labels at paper size; fitting a box alone is insufficient.
The known Nyamagabe/Nyaruguru 422/423 case is a project regression reference,
not a universal structure-number rule.

Project-owned front matter and setup stay in the printing library, starting
from a governed global sample. Use exact parties/logos/contract, fixed issue
date, simple external version and ordered cover/naming/key-map/drawing pages.
Internal hashes, paths, pending states and accepted residual receipts stay in
Working. Verify one legible `DS GridDesign by datasolutions.rw` credit per page.
Reuse verified unchanged vector artifacts; rerender affected proofs only.

Follow the destination project's current working agreements. For the TBEA
Nyamagabe/Nyaruguru delivery, compute on ds-server, transfer completed bytes
over Ethernet to Windows G: unless the owner authorizes an equivalent Drive
transfer, verify hashes and visibility, and make the requested Desktop shortcut
point to that Drive folder. Keep local renders, queued publication,
verified online artifacts and verified destination bytes distinct.
