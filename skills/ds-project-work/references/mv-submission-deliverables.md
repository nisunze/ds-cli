# MV submission deliverables

The one canonical list of what an MV submission or model-change delivery
contains. `ds-project-work`, `ds-boq-staking-table`, `ds-grid-project-model`,
`ds-pls-cadd-backup-delivery` and `ds-printout` all link here; none restates
it. Read it before assembling, checking or describing any MV submission, and
when the person asks what to hand over.

## The set

1. **Governed A3 plan/profile booklet.** The only printed MV plan/profile.
   Made by the `ds-printout` MV booklet workflow, never by PLS-CADD printing.
2. **Native PLS-CADD backup** (`.bak`). Made and proven by
   `ds-pls-cadd-backup-delivery`, including the fresh native Restore and
   reopen it requires before submission.
3. **Staking workbook: XLSX only.** It is never printed, never exported to
   PDF, and never turned into booklet pages or A3 sheets. A staking PDF in a
   submission is a defect, whoever asked for "the staking table".
4. **Five native PLS-CADD reports**, each as RTF plus an A4 PDF: Structure
   Usage, Section Usage, Section Sag-Tension, Summary and Terrain Clearances.
   These do not authorize PLS-CADD plan/profile printing.
5. **GIS, only where requested** (for example the alignment GeoJSON of the
   exact model revision). Do not add it unasked.

## The dated submission folder

A dated folder (`<yyyy-mm-dd>`, the day of the change) holds only artifacts
produced for that change, today. Never copy an earlier delivery, another
day's file or a superseded revision into it to make the folder look complete;
point to the earlier delivery by its revision or path in the record instead.
A file the change did not regenerate is not in the folder.

## Before saying it is ready

List the folder and compare it with the set above: every item the change
needs is present; no staking PDF or staking pages exist; nothing in it
predates the change. Record the folder and the exact model revision it was
built from in the project's delivery record (`ds-project-work`).
