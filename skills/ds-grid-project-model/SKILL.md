# Work with an already opened native Profile

Use the `ds` skill first. Discover the `grid-profile` MCP profile or the live
`map.profile.view` descriptor. Read the current native Profile context before
selecting, editing, calculating, or saving. Those operations remain independent;
a view or selection is not engineering acceptance or publication.

Discover each control from the installed surface and follow its authority,
confirmation, revision, and refusal contract. A stale revision requires a new
read and review; do not retry against an unreviewed head or change project to
force an operation. Retained native Profile controls do not expose a replacement
for the removed file command family.

For published design attachments, discover `design.attachment.versions`,
`design.attachment.show`, and `design.attachment.download`. MV attachments pin
a content revision and digest; LV attachments pin a governance version. Preserve
those identities and verify bytes through the owning command. Submission
contents are described in
[deliverables](../ds-project-work/references/mv-submission-deliverables.md).

Core no longer exposes the `dsgrid`, `dsgrid-exchange`, `library`, or `pls`
command domains. Model acquisition, typed package edits, spotting, conversion,
library seeding, and package publication stop at their independent owners.
Do not hand-edit package bytes or infer a replacement route.

Stops at: the independent engineering owner for an unavailable model workflow,
and native PLS-CADD for engineering acceptance and solver approval.
