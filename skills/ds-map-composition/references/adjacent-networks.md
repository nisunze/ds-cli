# Adjacent circuits on a focused transformer sheet

Use this when another transformer's LV or customer/service connections should
explain relationships within the focused sheet. Read the project layout and
its revision first. Discover `report.layout.edit` and its linked edit schema;
the atomic adjacent-network intent configures the complete context layer set
from the governed pen for each asset role and a versioned project policy. Save the result through the printing
library's governed command before publishing. A local recipe proof can test it
without changing project defaults.

Keep the focused transformer categorical where its approved setup is
categorical. Keep role, lifecycle and focus independent: a new transformer can
feed existing LV; neighbouring circuits can themselves be proposed or existing.
Use each feature's actual lifecycle field, retaining component-level details.
Never infer it from transformer nature, survey origin, proximity or model presence.
Unknown status uses the explicit neutral fallback. Retain transformer, customer,
service and pole symbols, casings, sizes and line patterns. The optional project
policy supplies three distinct subdued colours and opacity. With no override,
the resolved role documents own the colours and weights. Discover style resolve
and use the API's exact class/source/print/context/ink binding and revision.
Focused and neighbouring networks resolve independently. Unknown combinations
go to the style owner; printing consumers never seed or construct ids. The
style owner reviews the governed catalogue seed plan, retaining its backup and
version fences. Saved authored documents are never silently reseeded.
Colour the body and outline together when an explicit override is authorized. The starter
is customizable through governed print-style edits, without changing screen styles or the
focused pens. Context labels identify transformers; hidden customer identities
and electrical verdicts are not copied. The legend distinguishes each role and
its proposed/existing/unclassified categories from the focused network.

The export reads the complete active project roster and verified saved room
versions once, reusing held rooms at matching heads. Every neighbouring circuit
is retained for clipping by the actual focused viewport. A neighbour whose
transformer is outside the frame may still contribute a partially visible
line. Multiple neighbours and crossings must survive. An incomplete roster,
changed room or wrong owner refuses the export; no first-neighbour shortcut.

The focus, per-sheet camera exception and project padding determine the
usable extent. Context must not enlarge the fit to the whole project. Layer
ordering puts context below the focused circuits without replacing their pens.
Poles, customers, quantities and voltage-drop results in schedules and data
exports remain those of the focused transformer. A visible crossing is a
review observation, not a demonstrated connection or engineering defect.
Printing never moves, reconnects, merges or deletes network geometry.

Preview and paper use the same native projection. Previews read the host's
held active roster and rooms; missing holdings are named omissions, never
provider acquisitions or a silently incomplete context. Prepare rooms through
the declared project export/cache workflow and retry the draft. Record saved
versions, source/context digests and omissions alongside the render receipt.

Inspect one actual paper sheet and designer SVG with several neighbours,
an extent-edge circuit and a visible crossing. Check focused quantities and
voltage drop against the source run, readable identity labels, matching legend,
unaltered coordinates and complete focused-network fit. Red review circles in
an annotated reference are evidence, not new authored symbols. The
[owner's annotated example](../assets/adjacent-context-reference.png) shows where
neighbouring circuits should make those relationships visible.
