# Adjust one outlier transformer

Use an exception keyed by the exact canonical transformer and named layout.
Display title casing never changes that key. Read the project default and any
existing exception first; preserve other transformers, papers, outputs and
engineering geometry. A crowded outlier does not justify moving every sheet.

Discover the live layout editing schema and project/desktop printing contracts
through `ds capabilities`. CLI and MCP consume those same declarations and Rust
owners. Do not invent flags or a separate MCP control vocabulary.

## Choose the smallest supported adjustment

- Move or corner-anchor an independent table container; keep measured content
  inside the drawn border, with the requested gap. Parent-relative container
  edits come from the owner, not hand-added paper offsets. Explicit corner
  anchors constrain both placement and capacity profiles.
- Adjust authored font, physical row spacing, panel count or heading treatment
  within live bounds. Fill usable height before continuation; retain complete
  required rows and fields. Explicit unequal panel rows belong to layout
  authoring when the exception schema does not expose that control.
- Adjust legend controls, title-block text or per-layer visibility, colour and
  label treatment through supported print instructions. Keep live-map pens
  independent and retain other instructions when changing a single property.
- Column selection and Design/AsBuilt phase come from available source columns;
  discover whether the current exception schema can persist those changes.
  A draft edited layout is not proof of a supported saved-exception field.
- Adjust the transformer view using the owner's view controls when the problem
  is geographic fit rather than furniture. Preserve pinned source versions.

## Proof and persistence differ

When the discovered schema offers stepped network fitting and print-scale
limits, author those through its fit-policy intent. Name all populated required
engineering sources, use a physical clearance appropriate to symbols/labels,
and choose project scale bounds from the consultant's readability requirement.
The closest scale prevents a tiny design filling A0; the farthest bound must
still admit the complete network. Do not invent limits for an existing project
or hide a source to make it fit. The native assessment proves the resolved
scale and footprint. Keep accepted defaults unless the user selects the new
policy. Explicit cameras and automatic stepped fitting are alternative intents;
follow the schema's refusal rather than silently overriding the camera.

The layout editor's transformer-override intent applies a validated patch to a
local layout. Its transformer-instructions intent patches a settings document
for one transformer/layout and supports removing that exception. These are pure
Rust decisions; neither operation publishes the returned document.

For a headless proof, apply the patch to a draft and render the actual transformer
through the declared project preview/local-recipe export route. Restrict the
subject scope to that transformer. Do not save the modified draft as the common
project template just to make one exception permanent.

For saved per-transformer instructions, discover the provisioned desktop printing
preparation contract. It carries the explicit project, layout/revision, existing
output selection and the keyed exception map; removing an exception restores the
project default. Preserve selection and existing patches. It is currently the
publication route for these exceptions; the pure editor is not a headless save
command. Follow any lane/profile refusal without borrowing credentials.

## Check the result

Inspect the complete rendered page and readable table/map crops, then compare
an unchanged transformer. Verify row/field completeness, margins, corner anchors,
right-column alignment and source/recipe identities. Label-placement notes may
explain hidden text; they do not replace overflow or omitted-row checks. A local
artifact, saved exception and verified online print publication are separate
outcomes. Discover a fresh live contract before relying on a newer source build.
