# 02 — Exchange boundary: link a live PLS-CADD workspace, edit in DS Grid, delta-sync back

Source of the observations: `gaps/PLS-DSGRID-ROUNDTRIP-GAPS-2026-09-20.md` (G1–G13), all from `ds dsgrid-exchange` / `ds dsgrid model` receipts on the Nyamagabe workspace (PLS-CADD 16.81, DON 57).

## Observed today

- Import works: `inspect` → `plan --target dsgrid --crs <proj>` → `convert` → `validate` → `model import-external` (649 structures / 1982 sections; 10 unresolved external references; `.fea .pps .brk .tin` and 4 attachments retained as *dormant* members). It needs a **guessed CRS** (G1), and the working copy records no PLS source (G4).
- Export exists (`plan --target pls-folder|pls-bak`, `export_workspace.convert_to_16_81`, real 16.81 bytes) but writes a **new folder** (G3) and **drops** `.fea .pps .brk .tin`, the dxf and the logos (G2) — the members the consultant's points 1 and 3 live in.
- `.bak → pls-folder` restore is **refused** by the "16.81 authoring catalog" gate (CRI 94, 82 PLS-POLE v22 members, 19 library tuples unqualified) although `plan` said executable (G13).
- No `dsgrid model remove/rename` (G7); the application's own catalogue and the CLI's `native_local` catalogue **diverge** (G11); the application's *Connect workspace* stages the same folder as `LV`, 48 opaque members, unrecognised (G12); no UI target for the plan/profile view (G10); console mangles UTF-8 in names (G6); streamed drives not flagged (G9); unresolved references not named in the receipt (G5).

## Required

1. **Link**: `ds dsgrid model link --model local-<id> --workspace "<folder>" [--yes]` records `pls_source {path, digest, pls_version "16.81", member_versions {DON 57, CRI 94, FEA 15, …}, linked_at}`; `dsgrid model list` and `dsgrid model show` print it. `import-external` from an exchange output links automatically (the exchange report carries the pinned digest).
2. **Sync (DS → PLS)**: `ds dsgrid-exchange sync --model local-<id> [--into "<workspace>"] [--container folder|bak] [--dry-run] --yes` — writes **into the linked workspace**, rewriting only members whose engineering changed (DON 57; STRUCT 13 / PLS-POLE 22 placements; cable files; CRI 94 when criteria changed; FEA 15 when feature codes changed; XYZ 5 when terrain changed), leaves every other member **byte-identical** (`.pps .brk .tin`, attachments, libraries), keeps the DON's recorded home so PLS-CADD opens it without a "moved" dialog, and returns a member-level diff `{member, version, action: rewritten|unchanged|added, bytes}`. `--container bak` additionally assembles the exact-byte backup (existing `pls.backup-create` semantics).
3. **Pull (PLS → DS)**: `ds dsgrid-exchange pull --model local-<id> [--dry-run] --yes` re-reads the linked workspace after a PLS-CADD session, re-imports changed members only, and reports what changed under DS (structures moved/retyped, sections re-strung, criteria edited, feature codes edited) as a diff against the working copy's head; conflicts (both sides changed the same structure) are listed and refused unless `--prefer pls|dsgrid`.
4. **Restore**: `dsgrid-exchange convert --source <bak> --target pls-folder` succeeds for real 16.81 backups: the authoring catalog qualifies CRI 94, PLS-POLE 22, STRUCT 13 and the library tuples real workspaces carry, **or** unqualified members that DS did not touch pass through byte-identical. `plan` never says executable for a conversion `convert` refuses on the same pins.
5. **CRS**: `inspect` proposes CRS candidates that place the terrain inside the declared country (Rwanda TM `+proj=tmerc +lat_0=0 +lon_0=30 +k=0.9999 +x_0=500000 +y_0=5000000 +ellps=GRS80` first) with the `--expect-*` guard filled in; `--crs rwanda-tm` alias accepted.
6. **Catalogue**: `dsgrid model remove --model <id> [--keep-package]` and `rename`; one catalogue read by both the application and the CLI (the kernel's `native_local` store or the kernel as the app's store); `dsgrid model list` reports what the application has open. The application's *Connect workspace* / Import model uses the same `dsgrid-exchange inspect` and classifies the folder identically (same member count, kind, name).
7. **Receipts** name every member's `TYPE/VERSION/UNITS` read and written; unresolved external references are listed by name and class; sources on streamed/network volumes are flagged; console output is UTF-8.
8. **UI targets**: `map ui open --target dsgrid-plan|dsgrid-profile --ref local-<id>` for preview.

## Refusals

`workspace_not_linked`, `workspace_digest_moved` (source changed since link; run `pull`), `member_version_unsupported` (names member and version), `sync_conflict` (lists structures), `pls_version_writer_missing` (20.01), `catalog_unqualified_member` only when a DS-touched member cannot be emitted (never for pass-through), `streamed_volume` (warning, not refusal).

## Decisions taken while landing §1, §2, §7 (2026-09-20, plan 02-d6)

Silence in the contract was resolved to the smallest behaviour consistent with the existing `dsgrid` / `pls` contracts; each line below is now the contract.

1. **The link is the exchange digest.** `pls_source.digest` is the `sha256:` `ds dsgrid-exchange inspect` prints for the folder (order-sensitive over `(relative path, sha256(bytes))`), read by one shared folder walk (`ds_cli_dsgrid::folder`) used by `inspect|plan|convert`, `link` and `sync`. `link` refuses a folder that does not digest to the workspace the package preserved at import (`workspace_not_this_package`): a sync into another folder would write edits computed against a different baseline. Relinking replaces the link. `pls_source` also records `member_count` and `linked_at` (host clock).
2. **Auto-link needs the report beside the package.** `convert` now writes each source's absolute path beside its pinned digest into `exchange-report.json` (`sources[]`). `import-external` links only when that report sits beside the package, names exactly one PLS-CADD folder source, the package's preserved tree digests to the pin, and the folder still digests to it now; otherwise the receipt's `auto_link` says why and `link` is the explicit act. A package copied elsewhere (`dsgrid apply --out`) is never auto-linked.
3. **Sync writes the ORIGINAL bytes, verified through the export.** The export planner (`plan_workspace_export`) verifies the edit set on the healed engineering projection the import preserved; the sync applies the same classified edits with the same surgical ds-io writers to the exact original member tree (`pls-original-workspace.bak`), cross-checks every structure record (number, station, offset, definition leaf) of the patched original DON against the export's verified DON, and proves the DON home — the first header's `FILENAME='…'` and every structure reference under its directory — unchanged. That is what "keeps the DON's recorded home" means: the header and the absolute references are never rewritten; PLS-CADD sees the file at the path it recorded.
4. **Sync classes in this cut** (the delivery cut D6): structure retype and move (DON 57), the placed structure's description (DON 57, comment slot 1 = `structure_comment_1`, written in Windows-1252), the definition's description line (STRUCT 13, the line after the header), active terrain (XYZ 5). Whole-design materialization (added/deleted structures, re-strung sections, re-routed alignments), section projection, capacity-value edits and project-STR spotting edits refuse `sync_edit_class_unsupported` by name: they rewrite from the healed projection and have no original-tree writer yet. Cable files rewrite when contract 05/03 gives them a writer; today an edited cable is a whole-design offender and refuses. FEA 15 and CRI 94 pass through byte-identical with the diff note `unchanged (writer pending: 03)`.
5. **Two descriptions, two members.** `describe_structure` (01-B, `StructureRow.description`) lands in the placement's DON comment slot 1 — PLS-CADD's structure list prints it per placement. `StructureTypeRow.description` lands in the definition's STRUCT line — PLS-CADD prints it as *Structure Description* for every placement of that type. Neither writer touches the other's bytes; the export planner sees the type table unchanged (the sync reverts type descriptions before verification, since the definition line is not part of the pinned resource identity).
6. **Modes.** `--dry-run` and `--yes` are the two modes (the `pls terrain-reconcile` precedent): neither is `confirmation_required`, both is `mode_conflict`; a dry run is the same plan with the writes skipped. `--container bak --out <new.bak>` frames the synced tree through the container writer `pls backup-create` uses; a Restore of it lands at a new home (the "moved" dialog is expected after Restore; the folder container is the no-dialog path). `--into <folder>` writes into a copy that still digests to the link. Writes are atomic per member (temp file + rename); a member that fails to write stops the pass with the members already written named. `workspace_open` refuses on a PLS-CADD `.lock` or the DS open marker.
7. **Receipts.** Every member row names `TYPE VERSION UNITS` as read and as written, `action rewritten|unchanged|added`, bytes and sha256 before and after, and notes; the DON home; native structure numbers touched; unresolved external references by containing member (workspace path), reference and class (`structure definition | cable | criteria | feature codes | library | load case | attachment | sheet | unknown`); `verification` at level `proposal`. `streamed_volume` is a warning on `inspect|plan|convert|link|sync` when the path names a Drive stream, UNC share or cloud-synced folder (by path, no mount table is consulted). The Windows console code pages are set to UTF-8 at `ds` startup so a piped receipt reads as UTF-8 (G6).
8. **`--crs rwanda-tm`** on `plan|convert` expands to the engine's canonical Rwanda TM declaration; the plan id is the same as with the proj string. CRS *candidates* on `inspect` (§5 first half) are not landed.
9. **`dsgrid model show`** exists (the row, the package identity as its bytes declare it now, the link in full); `list` prints the link under each row.
10. **Deferred with their lines:** §3 `pull` (a workspace that moved is re-imported and re-linked today; the `workspace_digest_moved` remedy says so), §4 restore gate, §5 CRS candidates, §6 `remove|rename` and the one catalogue, §8 UI targets. `sync_conflict` cannot arise before `pull` exists.
11. **Acceptance note.** The raw `retype_structure` envelope on a strung structure is refused by model validation (`ATTACHMENT_POINT_FOREIGN_STRUCTURE_TYPE`: the supports still bind the old type's attachment points); the typed `ds dsgrid structure retype` of 01-B rebinds them. The retype writer was proven on the synthetic gate and the export's own retype gate; the mirror acceptance used describe + move.
