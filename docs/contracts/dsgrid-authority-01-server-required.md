## Required

1. **Window-free design family.** The 28 `design.*` window commands, the `map.design.*` room operations (open, read, select, set, create, delete, geometry, save, process, batch, report, pin, discard, layer-to-local, upload-to-local), `dsgrid.model.prepare-project`, the 8 `pm.*` and 9 `assets.*` window commands run with `headless_project` authority on the server, against the same governed objects the application uses, with the same refusals. The application keeps calling the same kernel commands. A `requires: window` descriptor remains only for `desktop.*` and the three pure-UI map commands (`map.ui.open`, `map.zoom`, `map.view`).
2. **Typed dsgrid commands over the engine** (all `authority none` on a package path, `headless_project` on a project head; every one with `--dry-run`, revision pin, `--yes`, receipt naming the engine operation id and the new revision):
   - `ds dsgrid alignment create|route|reverse|delete`, `ds dsgrid node create|move|delete`, `ds dsgrid edge create|delete`
   - `ds dsgrid structure create|move|retype|role|delete|describe` (description = the consultant's point 1)
   - `ds dsgrid structure-type author|geometry|attachment|list|show` (contract 05)
   - `ds dsgrid cable author|definition|curve`, `ds dsgrid section create|support|path|sag-mode|details|delete`
   - `ds dsgrid criteria weather|case|set|rule|binding|clearance` (contract 03)
   - `ds dsgrid feature-codes import|migrate|export|report` (contract 03)
   - `ds dsgrid terrain point|source|points|insert|elevation|delete|supersede`, `ds dsgrid policy author|delete`
   - `ds dsgrid analyse stringing|usage|demands|structure|topology|terrain-anomalies|clearance` (reads/solves; contract 06 attaches verification levels)
   - `ds dsgrid spotting plan|apply` (contract 04)
   - `ds dsgrid transaction apply` stays as the escape hatch for raw envelopes.
3. **Working copy as the default target.** Every typed command accepts `--model <local-id>` (the machine's working copy, journaled, becomes the next revision) or `--package <path> --out <path>` (immutable package → new package). `dsgrid model list` shows the head revision after each command.
   *Landed 2026-09-20 (01-B, `program/01b-d12`):* the working copy advances **in place under the same id** through the kernel's `local_models::Op::Revise` (package revision, digest and `head_revision` move on the catalogue row; name, origin, creation time, project pin and `pls_source` stay). The store checks the package digest the caller read under its lock, so two writers on one copy end in `revision_conflict`, never a silent overwrite. `--model` is found by id alone across this machine's catalogues of the lane (`--account` only when two accounts hold the same id → `local_model_ambiguous`). `dsgrid model show --model <id>` opens the package and prints the live authored head every `--revision` pin is read from. The family's plumbing is `ds-cli-dsgrid::mutation` (target, pin, dry-run/--yes, one receipt); a new typed verb is its inputs, its engine commands and its render.
4. **MCP parity**: the `ds_grid_model` chapter lists the same commands with the same descriptors.
5. **Receipts** name: engine operation id, descriptor digest, source revision → new revision, counts touched, warnings, and the PLS member versions affected when the working copy is linked to a workspace (contract 02).
   *Landed 2026-09-20:* `operations[] {operation_id, engine, semantic_version, descriptor_digest (sha256 of the published descriptor), journaled}`, `source_revision → resulting_revision`, `touched {commands, commands_with_effect, entities, tables}`, `deltas[]`, `warnings[]`, `pls_source` (the row's contract-02 link, null when unlinked) and `pls_members_affected[]` as `TYPE VERSION` from that link (`describe`/`retype` → `DON 57`; empty when unlinked or on a package).
6. **The first two typed mutations and the structure list** (D1/D2 of the delivery path), all `authority none`, `requires server`, MCP parity through the descriptors:
   - `ds dsgrid structure describe --model <id> --structure <id|number> --text "…" | --clear [--revision] --dry-run|--yes` → engine `describe_structure` (new journaled command; `StructureRow.description`, one trimmed line ≤ 500 chars, the placed structure's own text beside the library type's description). *Decision:* the description is a canonical column of the structures table (16th, nullable). *Amended at landing (2026-09-20, `land/01b-d12`):* the column is **additive** — it widens the schema the build WRITES, never what it READS. A package attested at the 15-column structures schema (every `.dsgrid` promoted before this build: Nyamagabe Model 1/2, Gisagara, the owner's Windows working copy `local-e9b0ccbf92d7447b`, the 18 Sep packages on the drive) opens unchanged with every `description` absent; `ds dsgrid inspect|validate|model show` name such members under `prior_schema_members[] {member, table, columns, current_columns}`; the first write (describe, retype, any revision) carries the current schema. The reader holds a member to the schema its manifest attests (`ds_grid_model::ipc::schema_lineage` — the current fingerprint plus each registered prior width; anything else is still `package_decode_failed`). Refusing the packages on disk, as `delivery_phase` (08-29) and granular tags (09-02) did, is not repeated: a promoted project head must keep opening. Contract 02 exports the text into the DON 57 structure record on sync.
   - `ds dsgrid structure retype --model <id> (--structure <id|number>)… [--from-finding structure_type_not_allowed] [--skip <id|number>]… --type <type-id|library-name> [--revision] --dry-run|--yes` → one engine `retype_structure` per structure, applied as ONE revision. *Engine decision:* `retype_structure` re-binds every strung support of the structure to the new type's attachment point with the same set label and slot (what PLS-CADD keeps on a structure-file substitution) and refuses by name when the new type lacks a strung set (a T-off's `30kV [set 4]`/`OPGW` cannot become a plain H-pole; `--skip` leaves such structures out of a batch). The REG angle-pole rule is evaluated before anything is written: the dry-run receipt lists `findings {cleared, remaining, created}`, and a write that would leave or create `structure_type_not_allowed` is refused with that code (contract 04).
   - `ds dsgrid report structures --model <id>|--package <path> [--out <file.csv|.xlsx>] [--only-findings] [--limit]` (contract 04 §5): engine read operation `report_structures`, CSV always, XLSX through `ds_io::layers_to_xlsx` (the stack's shared workbook writer; one sheet, the CSV columns plus the plan coordinate as `geometry_wkt`).
   - `--structure` and `--type` accept the id or, when unique, the engineering number / exact library name — an engineer types what the sheet prints; the receipt carries the id.

## Refusals (named)

`requires_window_retired` (a window-only path was requested by an old client), `revision_conflict`, `operation_not_admitted` (journaled op through `run`), `envelope_invalid`, `structure_type_unknown`, `alignment_unknown`, `dry_run_only` (a mutation on a promoted project head without a working copy).

*Landed 2026-09-20 (typed family):* `revision_conflict` (pin ≠ head, or the working copy advanced between read and write), `structure_type_unknown` (+ `structure_type_ambiguous` when one library name is held by two types), `structure_unknown`, `structure_required`, `confirmation_required` / `mode_conflict` (neither or both of `--dry-run`/`--yes`), `target_required` (neither or both of `--model`/`--package`), `local_model_not_found` / `local_model_ambiguous`, `package_decode_failed` (the package does not verify — damaged, or a table schema this build does not decode; an appended optional column is NOT that: 2026-09-20 landing), `model_validation_failed`, `command_invalid` (the engine's typed refusal, e.g. a strung set the new type lacks), `structure_type_not_allowed` (contract 04), `rule_source_missing`, `dry_run_only` (declared; reserved for a project-head target this cut does not admit — a project head is edited through a working copy: `dsgrid project download` → `model import-external`). `operation_not_admitted` keeps its implemented name `operation_not_read_only` on `dsgrid run` (renaming a released code breaks callers). `envelope_invalid` and `alignment_unknown` belong to `transaction apply` and the alignment verbs, deferred with them.

## Decisions taken while landing Required 1 (01-A, 2026-09-20)

Written here because the contract was silent; each is the smallest behaviour consistent with the existing `pm` / `assets` / `design` contracts.

1. **Retired transport, not retired codes.** A freed command keeps every refusal that names a *condition* (`work_not_permitted`, `work_revision_conflict`, `invalid_date`, `invalid_email`, `invalid_task_shape`, `invalid_assignment`, `too_many_assignees`, `nothing_to_update`, `confirmation_required`, `plan_unreadable`, `asset_*`) and drops the nine `desktop_*` pairing codes, which named the transport and cannot occur headless; documenting them would be a lie and `refusal_coverage` refuses undocumented-but-constructible codes either way. The headless set every freed command declares instead is `ds auth project status`'s (`headless_signed_out`, `headless_project_not_selected`, `project_context_stale`, `native_*`, `auth_*`), plus the route's own: `pm_refused` (ds-brain or the engine declined by name; `detail.service_message` carries the sentence), `task_not_found`, `record_not_found`, `project_not_visible` (404 = not a member).
2. **`requires_window_retired` is the parser's.** It fires for `--desktop-descriptor` on any `requires: server` command, documented once in `ds-cli/docs/contracts/cli-output-contract.md` like every parser code. There is no `--desktop-descriptor` "preview target" on `pm.*`/`assets.*`: nothing of theirs is previewed in a window. Map rooms (group d) are where an optional preview target has a meaning, and they decide it when they land.
3. **`pm.*` reads fold `get_graph` + `get_context` in the kernel; writes go through `commit_command` / `commit_batch`** — the four actions ds-brain's deployed canary (`00e3d50`) and prod already serve, so the freed commands work against today's deployment. The correspondence contract's server-side `record_list` / `record_read` / `task_read` actions (ds-brain `ffd73c5`, not yet deployed) EXTEND these reads when they ship; they do not replace them. `ds pm record list|read` therefore list records for the first time (the browser never fetched the context; `decodeProjectGraph` hard-coded `records: []`), bounded by ds-brain's 100 rows per context read and reported as `truncated`.
4. **Where the decisions live.** `ds_command_kernel::project_management::{reads, writes}` — the browser adapter's rules (`ds-web/src/lib/desktop/cli-pm.ts`) translated as they were, with the line they came from; the CLI is typed inputs and receipts. The TS adapter is left in place, unread by `ds` (TypeScript is read-only; removal is ledgered separately). `ds-cli-pm` no longer links the desktop bridge; the `tests/bridge_parity.rs` walks of `ds_cli_pm::BRIDGE_OPS` are removed with it. (That suite had been silently skipping on `run` since ds-web renamed `cli-work.ts` → `cli-pm.ts`; the stale fixture is fixed in the same commit.)
5. **Idempotency keys are the host's.** `command_id` is 128 bits of OS entropy minted in `ds-cli-auth` (`device::mint_command_id`); the kernel mints nothing. A `pm task create` without `--id` mints its task id the same way.
6. **Membership is the server's.** An elevated (platform-admin) credential reads every project but is a member of none by that fact; `pm task assign --request <me>` on a project the account is not a member of is refused by ds-brain (`pm_refused`, "every task assignee must be an active project member") and the receipt says so verbatim. Acceptance of the assign loop therefore names a member of the testing project.
7. **Ratchets.** `WINDOW_BACKLOG_TOTAL` 131 → 123 (`pm` 8 → 0) → 114 (`assets` 9 → 0); `ds-cli-pm` and `ds-cli-assets` leave the `WINDOW_COMMANDS` and `INVENTORY` ledgers. Context budgets untouched (two purposes trimmed to stay inside). No `CLIENT_PROFILE_SCHEMA` bump: `/api/v1/pm` and `/api/v1/assets` are hard-coded in the transport.
8. **`assets.*` — the catalogue is the door, the kernel decides what bytes are.** `ds-client-core::project_assets` sends the closed `POST /api/v1/assets` set (`tree`, `list`, `get`, `download`, `folder_create`, `folder_update`, `classify`, `attach`/`detach`, `ingest_start` → resumable upload → `ingest_finalize`); the CLI reads the file, digests it in one streaming pass, has the kernel recognise the head, and streams the bytes from the path named — the window never carried them. `read`, `preview`, `tree --into` and `promote` fetch through the signed read (32 MiB bound, digest-verified) and hand the bytes to `ds_command_kernel::assets` on this host; `preview --member` previews the member in the member's own format read off the container walk.
9. **The system-folder projection is not served headless in this slice.** `ds assets tree` renders the declared folders and the catalogued `a_` assets through the kernel's `tree::build`; the 19 inventory sources the application projects (`Transformers/…`, `MV models/…`, `Reports/…` …) are *not loaded* and named in `sources_omitted`; a `sys:` id given to a byte-level command is `origin_read_unavailable`. Loading those inventories headless is the "everything indexed in project Assets" campaign's work (each source has, or gains, its native door), not this contract's — deferred whole, with the fact left here.
10. **`promote` lands in the prepared local layer store**, the store `ds map local register` writes (`ds-layer-store::prepared`, scope = lane + the credential's uid), GeoJSON of one geometry type read from the features; other geo formats are `invalid_payload` (convert, or `read` them out). Effect `local_file_write`, no confirmation, as before.
11. **`attach --record <R-id>`** lands per the correspondence contract (`pm_record` link kind; the kernel `Link` gains `PmRecord`); the deployed canary already validates the record's existence.
12. **Retired bridge codes.** `asset_is_not_a_file`, `assets_offline_write`, `origin_unreachable` are minted only by the application's own adapter, which `ds` no longer reaches; `refusal_coverage` lists them as retired bridge codes (checked to still be minted, so the entry cannot outlive its reason). `ds-web` TypeScript is untouched (read-only; removal ledgered separately).
13. **Finding, not fixed here:** `assets list --folder <path>` on canary answers HTTP 500 from ds-brain (`assets_service_failed`) — the `folder_id`+`created_at` composite index is missing on that lane's Firestore. `tree --folder <path>` is the workaround; the index is ds-brain's to deploy.
