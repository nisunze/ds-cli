ds report project export — Export all transformer reports and maps headlessly in parallel.

  Export active transformers and named print outputs with project-wide
  numbering. Local layout proofs and draft SVG previews cannot publish.
  --publish queues Server sync; completion requires its publication receipt.
  Setups use held context; --seed acquires missing context. Photos require a
  media grant.

USAGE
  ds report project export [--transformer <name>] --out-dir <path> [--concurrency <n>] [--admin-bounds <path>] [--print-layout <json-file>] [--preview-layout <json-file>] [--context-vectors <dir>] [--seed] [--publish] [--server-state-dir <absolute-path>] [--lane <stable|canary>]

CONTRACT
  effect     local_file_write  (writes a file in your workspace)
  authority  headless_project  (a restored native user with explicit project context)
  execution  sync
  id         report.project.export   contract v1

INPUTS
  --transformer <name>                Explicit scope; repeat per name. Omit for every active saved transformer.
  --out-dir <path>                    Fresh directory to write into: one folder per transformer plus the batch receipt.  (required)
  --concurrency <n>                   Engines resident at once, 1..64. Default: min(scope, processors, 4).
  --admin-bounds <path>               Rwanda villages asset (.dsab). Default: the installed machine-shared asset.
  --print-layout <json-file>          Local proof replacement for an existing project layout; preserves engineering inputs and paper identity, records source/recipe digests, and cannot publish.
  --preview-layout <json-file>        One SVG preview per transformer, with outlined text and template pens; any draft id or paper. Cannot publish or combine with --print-layout.
  --context-vectors <dir>             Verified data.city-vectors output to use as this batch’s OSM/Microsoft map context.
  --seed                              Acquire the printed transformer's missing map context first (provider cost); without it unheld context is omitted and named.
  --publish                           Seal verified outputs for the matching native Server sync pump; without it, writes local reports only.
  --server-state-dir <absolute-path>  Matching `ds server serve --state-dir` directory when the Server uses a custom state root.
  --lane <stable|canary>              Deployment lane; stable is the default.  (default: stable)  (one of: stable, canary)

OUTPUT
  Lane, project, scope, engine identity, publication state, batch counts and
  receipt, context diagnostics and ordered transformer results: artifact
  inventory or typed error. --publish adds the Server-sync queue identity.

EXAMPLES
  ds report project export --out-dir ./reports --output json
      Every active transformer; `.data.results[]` says what each produced.
  ds report project export --transformer tx_a --transformer tx_b --out-dir ./reports --concurrency 2
      Two named transformers, two engines at once.
  ds report project export --transformer tx_a --out-dir ./reports --publish --output json
      Queue one verified report for Server sync; publication is separate.
  ds report project export --transformer tx_a --preview-layout ./draft.json --out-dir ./preview --output json
      tx_a's sheet as the draft composes it, with its pens, as one SVG page; `.data.preview` names the output.
